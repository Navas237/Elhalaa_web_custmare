## 1. Overview

The Digital Atelier `customer-web` is the **customer-facing Progressive Web App** that allows end-users to discover barbershop branches, browse barbers and services, and book appointments online.

It is the **public acquisition funnel** of the SaaS platform and must be:
- **Guest-friendly**: Anyone can browse branches without logging in
- **Fast**: SSR + ISR + skeleton loading for perceived performance
- **Secure**: Server-side booking validation, RLS-hardened, rate-limited
- **Mobile-first**: Bottom nav, safe areas, iOS zoom prevention
- **RTL-native**: Built for Arabic users first

## 3. Core User Stories

### US-1: Guest Discovery
> As a guest, I want to browse available branches so I can decide where to book without creating an account.

- Acceptance: `/shops` loads without authentication
- Acceptance: Shop cards show name, address, rating, image
- Acceptance: No shop internal data (owner_id, revenue) leaks

### US-2: Authentication
> As a customer, I want to register with my email and phone so I can book appointments.

- Acceptance: Signup requires email, password (≥8 chars), full name, phone (Egyptian format)
- Acceptance: Login redirects back to booking flow with encoded URLs
- Acceptance: Profile row auto-created atomically with email, name, phone

### US-3: Email Verification Gate
> As a business owner, I want only verified customers to book so I reduce spam and no-shows.

- Acceptance: Unverified users see: "يرجى تأكيد بريدك الإلكتروني لإكمال الحجز"
- Acceptance: Booking server action checks `user.email_confirmed_at`

### US-4: Barber & Service Selection
> As a customer, I want to choose my preferred barber and service before seeing available times.

- Acceptance: Flow: `/shops → /shops/[id]/barbers → /shops/[id]/services?barberId=X`
- Acceptance: Each step shows contextual info (shop name, barber name)
- Acceptance: Services grouped by category

### US-5: Smart Slot Booking
> As a customer, I want to see the best available time slots for my chosen barber and date.

- Acceptance: 7-day horizontal date picker (today + 6 days) based on **server time**
- Acceptance: Slots generated by **server-side** `get_staff_available_slots` RPC (10-min grid, packing-optimized, adjacent-preferring)
- Acceptance: All slots filtered against **server time** (`NOW()`) — past slots are never shown regardless of client device clock
- Acceptance: Only available slots shown (working hours minus occupied bookings)
- Acceptance: Time displayed in Arabic format (e.g. "١٠:٠٠ ص")
- Acceptance: **All** available slots are returned; top 5 are highlighted as "recommended" with a star icon

### US-6: Secure Booking Creation
> As a customer, I want my booking to be created securely without trusting client-side code.

- Acceptance: Booking created via **server action** `createBooking`, not raw client `.insert()`
- Acceptance: `client_id` is set server-side from `auth.uid()`
- Acceptance: Rate limit checked via `rate-limit-booking` Edge Function
- Acceptance: Duplicate pending booking prevented (DB trigger + pre-check)
- Acceptance: Double-booking prevented (GiST exclusion constraint + trigger)
- Acceptance: Overlap errors show Arabic user-friendly message
- Acceptance: **Defense in depth**: RLS + trigger + server action all validate independently

### US-7: Booking Confirmation
> As a customer, I want to see clear confirmation that my booking is pending barber approval.

- Acceptance: Success page shows: "في انتظار تأكيد الحجز" badge
- Acceptance: Displays service, shop, barber name, date, time, booking ID
- Acceptance: Links to profile and home

### US-8: Booking History
> As a customer, I want to see my upcoming and past bookings in my profile.

- Acceptance: Profile page splits into "Upcoming" (pending, confirmed) and "Past" (completed, cancelled)
- Acceptance: Each card shows: service name, status badge, date, time, barber name, shop name
- Acceptance: Status badges use color coding (orange=pending, green=confirmed, grey=completed, red=cancelled)

### US-9: Mobile Navigation
> As a mobile user, I want a bottom navigation bar for quick access.

- Acceptance: Bottom nav has 4 tabs: Home, Branches, Book, Account
- Acceptance: "Book" tab links to `/shops` (not bare `/booking`)
- Acceptance: Safe area support for notched phones
- Acceptance: iOS zoom prevention on inputs (16px font size)

## 6. Database Schema (Customer-Facing)

### 6.1 Tables Accessed

| Table | Purpose | Customer Access |
|-------|---------|-----------------|
| `shops_v2` | Branch info | SELECT (public, open only) |
| `shop_staff` | Barber roster | SELECT (public, via shop) |
| `services` | Service catalog | SELECT (public, active only) |
| `working_hours` | Barber schedules | SELECT (public, via shop) |
| `profiles` | User profiles | SELECT own, INSERT own, UPDATE own |
| `bookings_v2` | Booking records | SELECT own, INSERT own (via server action) |

### 6.2 Booking Statuses

| Status | Customer Label | Is "Unconfirmed"? | Is "Occupied"? |
|--------|---------------|-------------------|----------------|
| `pending` | قيد الانتظار | ✅ Yes | ✅ Yes (blocks slot) |
| `waiting_time` | — | ✅ Yes | ✅ Yes (blocks slot) |
| `confirmed` | مؤكد | ❌ No | ✅ Yes (blocks slot) |
| `completed` | مكتمل | ❌ No | ❌ No (slot released) |
| `cancelled` | ملغي | ❌ No | ❌ No (slot released) |

> **Note:** `no_show` status does not exist in the current database schema and is ignored.

### 6.3 Server-Side Slot Generation (RPC)

**`get_server_time(p_timezone)`**
- Returns: `server_date`, `server_time_minutes`, `timezone`
- Used by: Booking page to initialize date picker from PostgreSQL `NOW()`
- Ensures: Client device clock is **never** used for business decisions

**`get_staff_available_slots(p_staff_id, p_date, p_service_duration, p_timezone)`**
- Returns: All available slots for a barber on a given date, sorted by actual start time
- Columns: `display_start_time`, `actual_start_time`, `actual_end_time`, `score`, `is_recommended`
- Logic:
  1. Gets server time in shop timezone
  2. Fetches working hours for the day
  3. Generates 10-minute grid candidates within shift bounds
  4. Filters out past slots using `NOW()` (not client clock)
  5. Filters out slots overlapping with **occupied** bookings (`pending`, `confirmed`, `waiting_time`)
  6. Computes 10-minute visual overlap for display times only (actual times unchanged)
  7. Scores each slot: PDR (40%), adjacency (25%), earliness (20%), fragmentation (15%)
  8. Returns all slots; marks top 5 by `score` as `is_recommended`
- Security: `SECURITY DEFINER` — bypasses RLS to see all bookings for accurate availability

### 6.4 Constraints & Triggers

| Name | Type | Purpose |
|------|------|---------|
| `excl_no_double_booking` | GiST EXCLUDE | Prevents overlapping bookings per barber for occupied statuses only |
| `prevent_double_booking` | BEFORE INSERT/UPDATE | Belt-and-suspenders overlap check (occupied statuses only) |
| `prevent_duplicate_client_booking` | BEFORE INSERT | Blocks clients with pending/waiting_time bookings |
| `bookings_v2_check` | CHECK | Ensures start_time < end_time |

### 6.5 Key Indexes

| Index | Columns | Type |
|-------|---------|------|
| `idx_bookings_staff_date` | staff_id, booking_date | btree partial (occupied statuses) |
| `idx_bookings_v2_staff_date_display` | staff_id, booking_date | INCLUDE + partial |
| `idx_bookings_v2_upcoming` | booking_date, start_time | btree partial (active) |
| `idx_bookings_client_pending` | client_id, status | btree partial (pending/waiting_time) |
| `excl_no_double_booking` | staff_id, booking_date, tsrange | GiST |

## 7. Security Requirements

### 7.1 Authentication & Authorization

| Layer | Implementation |
|-------|---------------|
| Auth | Supabase Auth (email/password, JWT session) |
| Session | SSR cookie-based (`@supabase/ssr`) |
| Proxy | `src/proxy.ts` — refreshes session, protects routes |

### 7.2 RLS Policies (Customer-Relevant)

| Table | Policy | Rule |
|-------|--------|------|
| `shops_v2` | `shops_select_public` | `status = 'open'` — guests can browse |
| `services` | `services_select_public` | Active services of open shops |
| `working_hours` | `hours_select_public` | Hours of open shops |
| `profiles` | `profiles_select_own` | `(auth.uid() = id)` |
| `profiles` | `profiles_insert_own` | `(id = auth.uid())` |
| `profiles` | `profiles_view_active_staff` | Barber profiles visible to all authenticated |
| `bookings_v2` | `bookings_insert_client` | `(client_id = auth.uid())` |
| `bookings_v2` | `bookings_select` | `(client_id = auth.uid())` |
| `bookings_v2` | `bookings_client_cancel` | Can cancel own pending/confirmed bookings |

### 7.3 Anti-Abuse

| Threat | Mitigation |
|--------|-----------|
| Fake bookings | Server action + `client_id = auth.uid()` RLS + rate limiter |
| Double booking | GiST exclusion constraint + trigger (occupied statuses only) |
| Duplicate pending | DB trigger `prevent_duplicate_client_booking` + pre-check |
| Slot takeover race | `FOR UPDATE SKIP LOCKED` in trigger |
| Bot signup | Email verification required before booking |
| API spam | `rate-limit-booking` Edge Function (5/user/min, 20/IP/min) |
| Client clock tampering | All slot logic uses `get_server_time` / `get_staff_available_slots` RPC |
| Booking with forged data | Server action validates all fields; DB trigger re-validates overlap |

## 14. Appendix: Glossary

| Term | Definition |
|------|-----------|
| **GiST** | Generalized Search Tree — PostgreSQL index type for complex constraints |
| **RLS** | Row Level Security — per-row access control in PostgreSQL |
| **ISR** | Incremental Static Regeneration — Next.js caching strategy |
| **SSR** | Server-Side Rendering |
| **PWA** | Progressive Web App |
| **RPC** | Remote Procedure Call — PostgreSQL function exposed by Supabase |
| **Pending booking** | A booking with `status = 'pending'` awaiting barber confirmation |
| **Walk-in** | A booking without an associated customer account (`client_id = null`) |
| **Occupied status** | A booking status that blocks the slot (`pending`, `confirmed`, `waiting_time`) |
| **Released status** | A booking status that frees the slot (`completed`, `cancelled`) |
| **Server time** | PostgreSQL `NOW()` — the authoritative clock for all availability logic |
